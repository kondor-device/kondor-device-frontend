# Товарні фіди (Meta Catalog / Rozetka)

## Meta / Facebook Catalog

### URL фіда

```
https://www.kondor.ua/api/feed/meta
```

(локально під час розробки: `http://localhost:3000/api/feed/meta`)

- Формат: RSS 2.0 + `xmlns:g="http://base.google.com/ns/1.0"` (офіційний формат Meta Commerce Platform).
- Один `<item>` на кожен **колірний варіант** товару; варіанти одного товару об'єднані через `g:item_group_id` (= Sanity `_id` товару).
- `Content-Type: application/xml; charset=utf-8`.
- Джерело даних — Sanity (`GET_FEED_PRODUCTS_QUERY` в `src/lib/queries.ts`), товари з `showonmain == true` (банери категорій на головній) з фіда виключені.

### Мапінг полів

| Поле фіда | Джерело / логіка |
|---|---|
| `g:item_group_id` | `_id` товару в Sanity |
| `g:id` | `{_id_товару}-{код_кольору}` (складений — сирий SKU кольору не унікальний глобально по каталогу) |
| `g:title` | `generalname + name` (+ `, колір: ...`, якщо у товару кілька варіантів) |
| `g:description` | поле `description`, з очищенням від авторської markdown-розмітки (`* `, `**bold**`) |
| `g:link` | `https://www.kondor.ua/catalog/{slug}?color={колір}` |
| `g:image_link` / `additional_image_link` | фото кольорового варіанта (Sanity CDN) |
| `color`, `product_type` | колір варіанта, назва категорії |
| `g:brand` | `"Kondor"` (константа) |
| `g:condition` | `"new"` (константа) |
| `g:availability` | `outOfStock` → `out of stock`; `preorder` → `preorder`; інакше → `in stock` |
| `g:price` / `g:sale_price` | `price` / `priceDiscount`, формат `1199.00 UAH` |

Варіанти без жодного завантаженого фото пропускаються (Meta все одно відхилить offer без картинки).

### Кешування й оновлення

- Відповідь кешується (`export const dynamic = "force-static"` + `revalidate = 3600` в `src/app/api/feed/meta/route.ts`) — фід перегенеровується не частіше ніж раз на годину.
- Дострокове оновлення одразу після зміни товару в Sanity Studio — через вебхук `POST /api/revalidate`, підписаний HMAC-секретом (`SANITY_REVALIDATE_SECRET`). Деталі та інструкція з налаштування вебхука в Sanity — у коментарі на початку `src/app/api/revalidate/route.ts`.

### Налаштування в Meta Commerce Manager (виконати вручну, потрібен доступ до Business Manager)

1. **Commerce Manager → Каталоги → [ваш каталог] → Джерела товарів (Data sources) → Зафіксований фід даних (Scheduled feed)**.
2. Вставити URL: `https://www.kondor.ua/api/feed/meta`.
3. Частота оновлення: **раз на добу** (Meta й так частіше не тягне).
4. Формат файлу: **XML**.
5. Зберегти та запустити перший імпорт вручну ("Upload now" / "Завантажити зараз").
6. Перевірити у вкладці **Diagnostics** каталогу — Meta покаже помилки/попередження по конкретних товарах, якщо такі будуть (наприклад, невідповідність `google_product_category`, неякісні зображення тощо — це вже змістовна валідація з їхнього боку, недоступна без реального акаунта).

> Я не маю доступу до вашого Meta Business Manager, тому фактичний імпорт і перегляд Diagnostics потрібно зробити вручну. Локально фід вже перевірений скриптом-валідатором (див. нижче) на відповідність усім обов'язковим полям специфікації Meta — 0 помилок, 0 попереджень на 51 offer.

### Локальна перевірка (без Meta-акаунта)

Фід було прогнано через власний валідатор, що перевіряє відповідність [офіційній специфікації Meta Catalog](https://developers.facebook.com/docs/commerce-platform/catalog/fields/):

- XML коректно парситься (`xml.dom.minidom` / `ElementTree`).
- `rss`/`channel` мають усі обов'язкові поля.
- Кожен `<item>`: `g:id` (унікальність, ≤100 символів), `g:title`, `g:description`, `g:link`/`g:image_link` (валідні URL), `g:availability` (`in stock`/`out of stock`/`preorder`), `g:condition` (`new`), `g:price`/`g:sale_price` (формат `ЧИСЛО ВАЛЮТА`), `g:brand`, `g:item_group_id`.
- Результат на момент останньої перевірки: **51/51 offer без помилок і попереджень**.

## Rozetka (YML)

### URL фіда

```
https://www.kondor.ua/api/feed/rozetka
```

(локально під час розробки: `http://localhost:3000/api/feed/rozetka`)

- Формат: **YML (Yandex Market Language)** — `<yml_catalog><shop><currencies|categories|offers>`, окрема специфікація від Meta ([офіційні вимоги Rozetka](https://sellerhelp.rozetka.com.ua/p185-pricelist-requirements.html)).
- Один `<offer>` на кожен **колірний варіант** товару (як і в Meta-фіді).
- `Content-Type: application/xml; charset=utf-8`.
- Джерело даних — той самий `GET_FEED_PRODUCTS_QUERY`, спільна логіка формування id/посилань винесена в `src/lib/feed.ts`, щоб `id`/`link` товару були **байтово ідентичні** в обох фідах.
- Кешування й дострокове оновлення через вебхук — так само, як у Meta-фіда (`revalidate = 3600`, `POST /api/revalidate`).

### Мапінг полів

| Поле YML | Джерело / логіка |
|---|---|
| `offer id` (атрибут) | `{_id_товару}-{код_кольору}`, санітизовано під вимогу Rozetka (лише `A-Za-z0-9-`, без кирилиці й пробілів) — той самий id, що й `g:id` у Meta-фіді, лише "почищений" від символів на кшталт `_` |
| `available` (атрибут) | `false`, якщо `outOfStock`; інакше `true` (передзамовлення теж вважається доступним до купівлі — окремого стану "preorder" в YML немає) |
| `url` | те саме посилання, що й `g:link` у Meta-фіді |
| `price` / `price_old` | поточна ціна (з урахуванням знижки) / закреслена стара ціна (тільки якщо є знижка) |
| `currencyId` | `"UAH"` |
| `categoryId` | `cat._id` товару з Sanity; якщо в товару категорія не заповнена — службова категорія `uncategorized` / "Інше" (див. застереження нижче) |
| `picture` | усі фото кольорового варіанта (до 15 шт., ліміт Rozetka) |
| `vendor` | `"Kondor"` |
| `article` | сирий код кольору (SKU), для довідки — не використовується як id |
| `stock_quantity` | `0`, якщо `outOfStock`; інакше умовне `999` (Sanity не зберігає точний залишок на складі) |
| `name` / `name_ua` | те саме, що `g:title` у Meta-фіді (сайт лише україномовний, тому обидва поля однакові) |
| `description` / `description_ua` | те саме, що `g:description`, обгорнуто в `CDATA` |
| `state` | `"new"` (явно вказано, хоч це й значення за замовчуванням) |
| `param name="Колір"` | колір варіанта |

Варіанти без жодного фото пропускаються — так само, як і в Meta-фіді.

### ⚠️ Відома проблема з даними: товари без категорії

На момент реалізації **14 з 47 товарів у фіді (≈30%) не мають заповненого поля `cat` в Sanity** — серед них, наприклад, `Kondor Orion Nova`, `Kondor Orion PRIME`, `Kondor Moonlight X/PRO/PRIME`, `Kondor Legion PRO`, `Kondor Surface XXL/M`, комплекти кейкапів тощо.

Оскільки `categoryId` — обов'язкове поле в Rozetka (без нього offer не пройде валідацію), такі товари автоматично потрапляють у службову категорію **"Інше"** (`categoryId="uncategorized"`), щоб не випасти з фіда зовсім. Але це тимчасовий "запобіжник": для коректного розміщення на Rozetka (пошук/фільтри/категорійна сторінка на маркетплейсі) **потрібно проставити реальну категорію** цим товарам в адмінці Sanity.

### Локальна перевірка

- XML коректно парситься (`xml.etree.ElementTree`), корінь — `yml_catalog`.
- Усі `offer id` унікальні та відповідають вимозі Rozetka (`A-Za-z0-9-`, без кирилиці/пробілів).
- Усі `categoryId`, використані в `<offers>`, оголошені в `<categories>` (референційна цілісність).
- Результат на момент останньої перевірки: **51/51 offer**, 8 категорій (7 реальних + службова "Інше"), максимум 11 фото на offer (ліміт — 15), жодної ціни ≤ 0.
- Перед реальним підключенням фід треба прогнати через **вбудований валідатор Rozetka** (кабінет продавця → «Управління товарами» → «Валідатор») — там же видно й змістовні помилки (невідповідність категорій сайту, характеристик тощо), недоступні без облікового запису продавця.

### Підключення на боці Rozetka (виконати вручну, потрібен доступ до кабінету продавця)

1. Кабінет продавця Rozetka → **Управління товарами → Прайс-листи (або аналогічний розділ завантаження XML)**.
2. Вказати URL: `https://www.kondor.ua/api/feed/rozetka`, оновлення — раз на добу (або частіше, якщо дозволяє тариф).
3. Прогнати через **Валідатор** у кабінеті — виправити зауваження, якщо будуть.
4. Дочекатись підтвердження модерації менеджером Rozetka (стандартна процедура для нових товарів/категорій).
